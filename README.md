# payment-memo-encryption-java

本地转账的加密备注能力。转账可以携带任意文本备注，备注内容仅收款方可读。

## 设计概览

```
付款方 ──(1) ECDH + HKDF + AES-GCM──> 加密备注 ──> 转账流(文件日志)
                                                         │
收款方 ──(2) 按序扫描 + 解密 ──> 恢复的备注
```

## 密钥派生

每条备注使用独立的 X25519 临时密钥对，通过以下流程派生对称密钥：

1. **ECDH**：临时私钥与收款方公钥进行 X25519 密钥协商，得到 32 字节共享密钥。
2. **HKDF-SHA256**：以固定字符串 `payment-memo-encryption-v1` 为盐，
   以 `payment-memo-v1|<payeeId>` 为 info，从共享密钥派生 32 字节 AES 密钥。
   info 中绑定收款方身份，确保只有收款方持有的私钥才能完成相同派生。
3. **AES-GCM**：使用派生密钥对备注明文进行认证加密，IV 为每条备注随机生成的 12 字节。

### 密钥代次

收款方持有多个密钥代次（generation），每个代次有独立的 X25519 密钥对。
轮换（rotate）会将当前活跃代次标记为 RETIRED，并创建新的 ACTIVE 代次。
历史备注使用旧代次加密，轮换后仍可通过旧代次的私钥解密。
每条恢复的备注都会标记其对应的密钥代次。

### 信封格式

每条加密备注的信封（envelope）格式如下：

```
┌─────────┬──────────┬──────────────┬──────────┬──────────┬──────────────┐
│ version │ payeeId  │  keyGenId    │  临时公钥  │   IV     │  密文+标签   │
│ 1 byte  │ 2+N bytes│   8 bytes    │ 32 bytes │ 12 bytes │  remaining   │
└─────────┴──────────┴──────────────┴──────────┴──────────┴──────────────┘
```

信封头部（version 到临时公钥）作为 AES-GCM 的 AAD，绑定收款方身份、密钥代次和临时密钥。
任何对头部的篡改都会导致认证失败。

## 扫描位置

收款方通过扫描器（MemoScanner）按序扫描转账流：

- **检查点（checkpoint）**：记录最后一个已处理转账的 seq，持久化到
  `data/checkpoints/<payeeId>.checkpoint`。
- **连续前缀**：扫描器只处理从检查点之后开始的连续 seq 前缀。
  如果中间有空洞（某个 seq 尚未提交），扫描器会停止，等待该 seq 到达后再继续。
- **原子持久化**：每处理完一个转账，检查点通过临时文件 + 原子 move 持久化。
  崩溃后从最后一个已提交位置继续，不丢失、不重复。

### 批次无关性

扫描输出与批次大小无关。无论使用 `scanBatchSize=1` 还是 `scanBatchSize=100`，
扫描器都按 seq 顺序处理，输出顺序确定一致。

## 一致性语义

### 提交语义

- **幂等提交**：每个转账携带客户端生成的 `requestId`。
  相同 `requestId` 的重复提交只产生一条转账（通过 `requests/<requestId>` 标记文件保证）。
- **原子发布**：转账内容先写入临时文件，再通过原子 move 发布为最终文件。
  已提交的转账立即可被扫描恢复，未提交的不会被恢复。

### 扫描语义

- **按序恢复**：扫描器按 seq 升序处理，恢复的备注按转账顺序排列。
- **失败隔离**：解密失败、校验失败、代次未知等失败被记录但不阻止后续扫描。
  失败原因可区分：`MALFORMED`（信封结构损坏）、`UNKNOWN_GENERATION`（代次未知）、
  `DECRYPTION_FAILED`（认证失败或密钥不匹配）。
- **不重复**：检查点确保每个转账只被处理一次。
  重新扫描时，已处理的转账不会重复输出。

### 崩溃恢复

- 检查点在每个转账处理后持久化。崩溃后重启，扫描器从最后一个已提交位置继续。
- 如果崩溃发生在检查点持久化之前，重新扫描会重新处理该转账。
  输出接收方应通过备注唯一标识（transferId + memoIndex）去重。

### 导出导入

- 收款方可导出全部密钥代次（用密码加密，PBKDF2-HMAC-SHA256 + AES-GCM）。
- 新实例导入导出材料后，可恢复全部历史备注的解密能力。
- 导入后的扫描结果与导入前逐条一致（明文、密钥代次、seq 相同）。

## 配置

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `memo.max-length` | 4096 | 单条备注最大字符数 |
| `memo.max-memos-per-transfer` | 20 | 单笔转账最大备注条数 |
| `memo.scan-batch-size` | 50 | 扫描批次大小 |
| `memo.data-dir` | `./data` | 数据存储目录 |

超限请求被确定性拒绝（抛出 `IllegalArgumentException`）。

## API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/transfers` | 创建转账（携带加密备注） |
| POST | `/api/scan?payeeId=xxx` | 扫描转账流恢复备注 |
| POST | `/api/keys/rotate?payeeId=xxx` | 轮换密钥代次 |
| POST | `/api/keys/export?payeeId=xxx&password=xxx` | 导出密钥材料 |
| POST | `/api/keys/import` | 导入密钥材料 |
